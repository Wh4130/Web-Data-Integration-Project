## Wikidata — attribute extraction & conflict resolution

Another source of airport data is Wikidata. Although we attempted to query official Wikidata SPARQL engine, the endpoint eventually failed to response due to its limited throughput. We alternatively implemented the query with the QLever SPARQL engine, provided by University of Freiburg. Attributes of interest include airport (wikipedia url), name, country and city, geometric data such as coordinate and elevation, timezone, owner, operator, and standardized identifiers (IATA, ICAO, FAA).

We found that several airport entities hold multiple values in one attribute. Some of these are legitimate (e.g., an airport operated by several organizations, or current and historical values stored side by side), while others likely stem from the collaborative, crowd-sourced editing of Wikidata, which leads to redundant or conflicting statements. To handle this, we queried each attribute separately, concatenated the results into a long-format table (one row per combination of entity, attribute, and value), and aggregated it by the airport column into a wide-format table. We further conducted conflict resolution of attribute values: attributes that reasonably take multiple values are aggregated into a list attribute (owner and operator), while other attributes with low conflict rate are resolved into a singular value with the mode value. A special case is coordinates, which are resolved as a (latitude, longitude) pair rather than independently per axis: resolving each axis separately could combine a latitude from one source statement with a longitude from another, producing a coordinate that no single statement ever actually asserted. Finally, attributes that should uniquely identify an airport, such as the IATA code, were likewise resolved to a single value per entity using the mode-based approach.

A seperate issue arises from identifiers that are expected to be globally unique but are not: the same IATA, ICAO, or FAA code occasionally appears across two or more different airport entities (under 1\% of non-null values for each identifier). To distinguish a genuine data error from a true duplicate, we classified each duplicated code value by the geographic distance between the entities sharing it. Entities far apart (distance calculated by coordinates larger than one kilometer) were judged to be distinct airports that happen to share an unreliable code. In this case, the code itself was set to missing rather than attributed to either entity. On the other hand, entities close together were perceived the same airport recorded as two separate Wikidata resources. These are merged into a single row, with the more complete among all retained as the primary record and the other coaleseced into it then dropped.
